Case Study: Portal Personal de Salud

Health Information System Auditing and Validation

Functional Analyst: Soledad Varady
May - August 2025
Digital Corporate Health

Executive Summary

The Challenge

Sports industry companies like Nike, Adidas, and Under Armour needed a system allowing employees to autonomously manage their personal medical information while ensuring clinical validity through professional auditing by certified physicians.

My Role as Functional Analyst

I was responsible for:

  • Complete specification of functional and non-functional requirements
  • Design of use cases and system interaction flows
  • Creation of sequence diagrams documenting technical integrations
  • Development and execution of test cases for functionality validation
  • Identification and documentation of critical pre-production defects

Key Results

  • 23 requirements specified (18 functional, 5 non-functional)
  • 3 main use cases documented with UML diagrams
  • 8 test cases executed with 100% coverage of critical flows

Impact

Early detection of critical defects in filtering modules and SNOMED CT coding prevented the launch of a system that would not have met its primary functional objectives, saving significant post-implementation correction costs and protecting the project's reputation.

  4. Testing & Validation (June 2 - August 30): Test case design, functional testing execution, defect documentation

Critical Findings

🔴 Critical Defect: SNOMED CT Coding System Non-Functional

Most Important Testing Discovery

Context: SNOMED CT coding is the functional heart of the Personal Health Portal. Without coding:

  • Data cannot be validated by auditors
  • Information cannot be transferred to EHR
  • There's no interoperability with other clinical systems
  • The system doesn't fulfill its primary objective

Problem Identified: When attempting to search clinical terms for coding, the system consistently returns:

HTTP 404 Not Found
ClientErrorException: Got an HTTP status code 404 error

Technical Impact

Expected Flow:

Auditor → Enter "hypertension" → Request to /snomed/search?term=hypertension → SNOMED CT Service → Response with codes → Display results

Actual Flow:

Auditor → Enter "hypertension" → Request to /snomed/search?term=hypertension → ❌ ERROR 404 → User sees empty modal

Root Cause Hypotheses

  1. Incorrect or unconfigured endpoint
  2. SNOMED service not deployed
  3. Authentication problem
  4. CORS not configured
  5. Malformed parameters

Additional Defects Detected

🔴 High Priority: Incorrect Classification in Filters

Problem: Fully validated patients remain in "PARTIALLY VALIDATED" state.

Impact: Auditor cannot trust filters for work prioritization. Must manually review each patient to verify actual status.

🟡 Medium Priority: Confusing Message When Rejecting Information

Problem: When rejecting information with "NOT VALID", system shows success message (green color, generic text).

Impact: Generates confusion in auditor. May lead to manual status verification.

Conclusions

System Status

⚠️ System NOT ready for validation or production

Blocking defects pending resolution:

  • 🔴 BUG-02 (CRITICAL): SNOMED CT search returns Error 404 - System unusable for its main purpose
  • 🔴 BUG-01 (HIGH): "Validated" filter incorrectly classifies patients

Formal Recommendation

❌ DO NOT PROCEED to:

  • Validation with end users
  • Production environment deployment
  • User training

✅ NEXT STEP:

  1. Resolve BUG-02 (SNOMED CT service)
  2. Resolve BUG-01 (filter logic)
  3. Re-execute Test Cases 123 and 124
  4. If both PASS, proceed to complete patient module testing
  5. Only then consider user validation

Lessons Learned

✅ What Worked Well:

  • IEEE 830 standard documentation provided clear structure
  • UML diagrams enabled visualization of user-system interactions
  • PSeInt prototyping validated business rules early

⚠️ Areas for Improvement:

  • Earlier testing would have allowed parallel corrections during design
  • Integration validation should occur BEFORE designing dependent flows
  • UI prototypes would have reduced interpretation ambiguity
